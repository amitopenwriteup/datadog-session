
Workflow Automation dashboard opens.

# Module 4: Configure Trigger

## Objective

Start workflow automatically from a monitor alert.

### Step 1: Add Trigger

Select:

```
Datadog Monitor Trigger
```

### Step 2: Configure Trigger

| Setting | Value |
|----------|--------|
| Monitor Type | Metric Monitor |
| Alert State | Alert |
| Metric | CPU Utilization |

### Example Trigger Condition

```
CPU Utilization > 80%
```

Save configuration.

### Expected Result

Workflow starts whenever the monitor enters Alert state.

---

# Module 5: Add Notification Action

## Objective

Notify teams automatically.

### Step 1: Add Action

Click:

```
Add Action
```

Select:

```
Send Slack Message
```

### Configure Message

```text
High CPU detected on host:
{{host.name}}

Current CPU:
{{cpu.value}}

Investigation required.
```

### Expected Result

Slack notification is sent automatically when alert occurs.

---

# Module 6: Create Incident Automatically

## Objective

Automate incident creation.

### Step 1: Add Action

Select:

```
Create Incident
```

### Configure Incident

| Field | Value |
|--------|--------|
| Title | High CPU Incident |
| Severity | High |
| Service | Production |

### Incident Template

```text
Automated incident generated by Workflow Automation.

Monitor:
{{monitor.name}}

Host:
{{host.name}}

CPU:
{{cpu.value}}
```

### Expected Result

Incident is created automatically when alert is triggered.

---

# Module 7: Add Approval Step

## Objective

Require human approval before remediation.

### Step 1: Add Action

Select:

```
Approval Request
```

### Configure

| Setting | Value |
|----------|--------|
| Approver | Operations Team |
| Timeout | 30 Minutes |

### Expected Result

Workflow pauses until approval is received.

---

# Module 8: Automated Remediation

## Objective

Execute corrective actions automatically.

### Example Remediation Actions

#### Restart Service

```bash
systemctl restart application.service
```

#### Restart Kubernetes Pod

```bash
kubectl rollout restart deployment/webapp
```

#### Trigger Lambda Function

```json
{
  "action": "restart-service"
}
```

### Configure Action

Add:

```
HTTP Request
```

or

```
AWS Lambda
```

action.

### Expected Result

Remediation action executes after approval.

# Module 9: Testing Workflow

## Objective

Validate workflow functionality.

### Test Procedure

1. Trigger monitor manually.
2. Verify workflow execution.
3. Confirm Slack notification.
4. Verify incident creation.
5. Approve workflow.
6. Confirm remediation action executes.

### Validation Checklist

| Validation | Status |
|------------|---------|
| Workflow Triggered | ✓ |
| Slack Message Sent | ✓ |
| Incident Created | ✓ |
| Approval Requested | ✓ |
| Remediation Executed | ✓ |

# Challenge Exercise

## Scenario

A production service experiences high CPU utilization.

### Requirements

Create a workflow that:

1. Detects CPU > 80%
2. Sends Slack notification
3. Creates incident
4. Requests approval
5. Restarts service
6. Posts resolution update

### Bonus

Add automatic rollback if remediation fails.

- Audit workflow actions

## Reliability

- Add retry mechanisms
- Configure failure notifications
- Test workflows regularly
